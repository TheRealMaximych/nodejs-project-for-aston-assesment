## Why

Оценка J3 проверяет рабочий backend (auth, счета, переводы, баланс, история). Swagger UI уже есть, но для быстрой ручной проверки удобнее одна страница с формами: логин → Bearer в памяти → вызовы существующих эндпоинтов → HTTP status и сырой JSON. Это не продукт и не «фронтенд оценки», а тонкая локальная обвязка над готовым REST.

## What Changes

- Добавить одну статическую страницу (HTML + немного CSS + vanilla JS) с блоком на каждый существующий эндпоинт: поля тела/path, кнопка Send, показ status и JSON (успех и `{ error, statusCode }`).
- Отдавать страницу тем же Express, что и API: `GET /` из папки `public/`. Без второго dev-сервера, без SPA-стека, без bundler, без CORS (один origin).
- После `POST /auth/login` сохранять `accessToken` в памяти JS и автоматически слать `Authorization: Bearer` на защищённые запросы. Logout очищает токен в UI.
- В README — одна короткая строка, как открыть UI после `npm run dev`. Без архитектуры.
- HTTP-runtime: путь UI публичный (как `/api-docs`): не unknown 404 и не 401 из‑за отсутствия Bearer.

## Non-goals

- Не менять контракты REST, статусы, тела ошибок, домен, сервисы, репозитории, миграции, seed, OpenAPI-схемы (кроме того, что UI-путь не 404 и не требует JWT).
- Не добавлять эндпоинты предметной области, депозит, список счетов, dashboard, клиентский роутинг, логин-экран как продукт, банковскую валидацию на клиенте.
- NestJS, MongoDB, Redis, GraphQL, OAuth2, refresh-токены, подтверждение email, сброс пароля, Docker-образ приложения.
- Не unit-тесты фронта. Не логировать JWT/пароль на сервере из‑за UI (UI только `fetch` с клиента).
- React/Vue/Angular/Svelte, Vite/Webpack, CSS-фреймворки, UI-kit, отдельный npm-пакет UI.

## Capabilities

### New Capabilities

- `api-check-ui`: одна статическая страница проверки API на том же origin, что и REST; формы строго по существующему контракту; Bearer в памяти после login; показ status и сырого JSON.

### Modified Capabilities

- `http-runtime`: `GET /` (страница проверки API) — публичный маршрут, как `GET /api-docs`: не unknown-path 404 и не 401 только из‑за отсутствия Bearer; успешный ответ MAY быть HTML.
- `runbook-readme`: README MUST содержать одну короткую строку с URL UI после `npm run dev` (пример порта из `.env.example`). Без описания архитектуры.

## Impact

- Файлы: `public/` (статика), `src/http/app.ts` (`express.static` до `notFound`), `README.md` (одна строка URL). Сервисы, репозитории, сущности, миграции, seed, OpenAPI-документ — без смысловых правок.
- API: доменные контракты не меняются. Новый публичный путь только для статики UI.
- Зависимости: новых npm-пакетов нет (`express.static` уже в Express).
- Тесты: новых фронтовых тестов нет. `npm test` и `npm run build` остаются зелёными.
- Секреты: токен только в памяти браузера; сервер не логирует JWT/пароль из UI.
